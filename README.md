# RuView Observatory

**Mission-control dashboard for WiFi CSI sensing — tactical situational awareness, fully self-contained.**

The RuView Observatory is a static, zero-dependency web application that visualizes the sensing output of a RuView-style WiFi Channel State Information (CSI) mesh: presence and motion contacts on a tactical sector map, breathing and heart-rate vitals, a live 56-subcarrier RF spectrum, ESP32 sensor-mesh health, and an alert feed. It runs entirely on the client — no backend, no cloud, no live signals — driven by a deterministic simulation engine so it deploys and works anywhere.

> **Simulation only.** All data shown is synthetic, generated by a seeded simulator. This project contains no live sensing, no real signals, and no tracking of persons. It is a demonstration and situational-awareness training interface for authorized environments. See [docs/SECURITY.md](docs/SECURITY.md).

## Features

- **Tactical sector map** — 48-cell grid with occupancy overlay, motion highlighting, contact tracks with velocity vectors, detection circles, and mesh-node coverage rings.
- **CSI spectrum** — live 56-subcarrier amplitude chart with breathing modulation and interference-burst highlighting.
- **Vitals monitor** — breathing (BPM) and heart-rate (BPM) sparklines for dwelling contacts.
- **Sensor mesh** — ESP32 node table: RSSI, battery, packet rate, uptime, and status (online / degraded / offline) with recovery alerts.
- **Alert feed** — severity-ranked timeline (presence, motion, RF interference, node loss/recovery).
- **Sensor console** — event log with UTC clock and IST (+05:30) local time.
- **Controls** — pause/resume, 1×–8× speed, one-click reset (replays the same mission deterministically).
- **Tested & CI-verified** — 14 unit tests for the simulation engine (`node --test`), deterministic and reproducible; GitHub Actions builds and deploys to GitHub Pages.

## Quick start

Requires Node.js 20+ (no runtime dependencies).

```bash
npm test          # run the test suite (node:test) — 44 tests
npm run build     # validate + copy the site to dist/
npm run serve     # local preview at http://localhost:8080
npm run ground-truth   # Phase 1 validation report (synthetic baseline)
```

Then open `http://localhost:8080/`.

## Phase 1 — WiFi device counting (metadata only)

A lawful, privacy-by-design acquisition pipeline for counting live WiFi
devices from probe-request/association **metadata only** — no payload, no
content, no identification. Raw MACs are anonymized (salted HMAC) before any
storage; zone attribution via SSID→zone map; append-only audit log.

```
acquisition/   frames.js · pcap.js · anonymize.js · clusterer.js ·
               counter.js · pipeline.js · mock-adapter.js · evaluation.js · audit.js
server/api.js   operator HTTP API (health / devices / stats / events)
scripts/        ground-truth.mjs (validation harness) · capture.mjs (live capture)
```

### Live capture (Linux host + monitor-mode NIC)

```bash
sudo ip link set wlan0 down
sudo iw dev wlan0 set type monitor
sudo ip link set wlan0 up
npm run capture -- --iface wlan0mon --port 8181 --zones acquisition/zones.example.json
```

Or replay a pcap file (no hardware): `npm run capture -- --file capture.pcap`

## How it works

1. **Engine** (`src/observatory.js`) — pure, deterministic logic: contacts patrol waypoints on the sector grid, dwell and show vitals, a seeded PRNG drives the RF spectrum, mesh health, and events. Same seed → same mission, every time.
2. **Render layer** (`src/ui.js`) — stateless drawing onto canvases and DOM panels.
3. **Bootstrap** (`src/main.js`) — runs the engine at 60 fps, wires controls, logs events, keeps clocks.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the full data flow and extension points.

## Deployment

The GitHub Actions workflow (`.github/workflows/static.yml`) builds and deploys the site to GitHub Pages:

- On push to `main` (or manual dispatch), CI runs `npm ci → npm test → npm run build` and publishes **only `dist/`**.
- The `github-pages` environment has branch-protection rules that allow deployments **from `main` only**. Feature branches build and test but cannot deploy until merged into `main`.
- GitHub Pages must be enabled with **GitHub Actions** as the source (Settings → Pages → Build source: GitHub Actions). See [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) for the full procedure.
